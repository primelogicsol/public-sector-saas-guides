# Role-Based Access Planning

Role-based access control helps ensure that users only perform actions appropriate to their responsibilities.

## Example Roles

| Role | Typical Access |
|---|---|
| Public Viewer | View published information only |
| Field User | Submit field records and observations |
| Reviewer | Review submitted records and request corrections |
| Approver | Approve records, reports, or workflow decisions |
| Program Manager | Manage program-level records, workflows, and dashboards |
| System Administrator | Manage users, roles, configurations, and integrations |
| Auditor | View records, logs, evidence, and approval history |

## Access Planning Checklist

- Define roles before building screens.
- Separate view, edit, approve, export, delete, and publish permissions.
- Avoid giving broad administrative access by default.
- Preserve audit logs for critical actions.
- Review role assignments regularly.
- Document who can access sensitive operational data.

## Design Principle

Permissions should follow institutional responsibility, not convenience.
