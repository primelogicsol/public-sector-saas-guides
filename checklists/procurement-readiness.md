# Procurement Readiness Checklist

This checklist helps agencies, utilities, NGOs, and institutional buyers prepare for a software discovery or procurement conversation.

## Organizational Readiness

- [ ] Program owner identified
- [ ] Technical contact identified
- [ ] Procurement contact identified
- [ ] Security or IT reviewer identified
- [ ] Data owner identified
- [ ] Legal or compliance reviewer identified, if required

## System Scope

- [ ] Problem statement documented
- [ ] Current workflow mapped
- [ ] Required users and roles identified
- [ ] Required dashboards listed
- [ ] Required reports listed
- [ ] Data sources identified
- [ ] Integration needs identified
- [ ] Public-facing components identified

## Governance

- [ ] Access control expectations defined
- [ ] Audit logging requirements defined
- [ ] Data retention expectations defined
- [ ] Backup and recovery expectations defined
- [ ] Accessibility expectations defined
- [ ] Privacy and confidentiality expectations defined

## Procurement Notes

A stronger procurement conversation begins when the buyer can clearly describe the operational problem, responsible users, data sources, expected decisions, and reporting obligations.
